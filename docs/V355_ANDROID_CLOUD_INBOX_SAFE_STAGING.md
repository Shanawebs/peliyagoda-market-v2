# Market Pro V3.5.5 — Android Cloud Inbox Staging and Conflict Safety

**SOURCE-ONLY, NOT DEPLOYED. NOT THE FINISHED TWO-PHONE SYNC.**

## Implemented

- Non-destructive Room **6→7** migration adds `cloud_inbox_snapshots` and `cloud_inbox_cursors`. Existing purchases, requisitions, items, addition lots, cash, Other Expenses, invoice photos, Cloud identities, pending upload journal and auth tokens remain untouched.
- Cloud Inbox DAO stores each received server row by **(entityType, canonical Cloud UUID)** with revision, server update timestamp, tombstone field, JSON and receive time.
- Room cursors are per remote entity type (category, item, requisition, purchase, addition, cash), committed in the **same Room transaction** as verified page snapshots, and checks the previously saved cursor before accepting a batch. This prevents competing downloads from silently skipping pages.
- `CloudInboxPagePolicy` checks ordered keyset pages, server business date format, allowed entity types, UUIDs, monotonic revisions, max 100 rows, continuity with requested cursor and a truthful last-row cursor.
- `CloudInboxStager.stagePage` parses an authenticated server response envelope, checks each row belongs to expected workspace and uses an allowlist of columns. It explicitly rejects photos, operations ledger and other unexpected keys, and detects local pending edits through `cloud_sync_outbox` + `cloud_entity_ids`.
- Higher Cloud revisions update ONLY the shadow/inbox table. Same/older revisions skip; pending local changes are counted as **conflicts requiring reconciliation**, not overwritten. No domain table (purchases/requisitions/cash/others) is edited. No local outbox entries are deleted or generated by a remote page.
- Kotlin tests cover page order, duplicate/rollback/bad cursors, UUIDs, server date validity, record count limits and monotonic revision.
- GitHub CI runs Android Kotlin/Room tests and existing V3.5.4 disposable PostgreSQL 17 server upload/download tests, plus strict old Web Dashboard source freeze check.

## Why inbox staging matters

Existing Room tables have item IDs as local `Long` values and cloud records identify items by global UUID. A direct blind Cloud upsert into `MarketDao.savePurchase` would risk linking the price to the WRONG item or overwriting the owner's local unsynced change. **Staging is not a substitute for a verified canonical UUID-to-local-ID mapping.**

## Missing before any real two-phone deployment

1. Active authenticated **network download transport** calling the proposed server `marketpro_team_pull_page`; proposals are still source-only, not deployed.
2. Separate owner and staff Supabase Auth accounts and enrolled device identities. Never share owner password or promote a staff device through old V3.3.7 owner-only RPC.
3. Atomic **Cloud inbox → Room domain merge** after authoritative mapping of category, item UUID, requisition/purchase/cash record UUID and receipt revision. Existing purchase additions use auto-increment IDs, so they especially require careful stable identity translation.
4. A storage layer for per-record last-applied revisions, conflict resolution for unsent offline edits, and old-date staff read-only enforcement at both UI and server.
5. An incremental polling or catch-up loop + WorkManager scheduler (and Realtime signal when foreground); keyset paging alone is not guaranteed atomic across a moving snapshot. Recheck overlaps/watermark and refresh after restart.
6. User-visible edit/conflict corrections and staff login/account invitation UI; test with two real phones incl. midnight Asia/Colombo, 4GB RAM, offline queues, clean reinstall, invoice photo backup.
7. `daily_other_expenses` new Supabase table, RPC, RLS and backend finance summary. **Old dashboard visual design must stay unchanged**, and existing dashboard URL/login continues.
8. Backup, test evidence, stable Android signing/device identity continuity and audited staged production rollout.

**No new APK released from this branch.** It is source-only because a partial inbox is not safely usable as a full two-way synced Market Pro app. Working live **V3.3.7 sole Cloud writer** and original web dashboard are not edited.
